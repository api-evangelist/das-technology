# DAS Technology

> DAS Technology (formerly Digital Air Strike) is an automotive-retail customer-data and
> experience company serving more than 9,300 dealerships, retailers, partners and OEMs. Its CDXP
> (Consumer Data & Experience Platform) unifies advertising, lead response, reputation management

## What the API is

The **DAS Web API** (`DASWebAPI`) is an ASP.NET Web API hosted on Azure at
`https://api.digitalairstrike.com`. Two versions are served concurrently and documented by two
Swashbuckle-generated Swagger 2.0 documents, both of which are anonymously readable:

- `https://api.digitalairstrike.com/swagger/docs/v1` — DASWebAPI V1, 104 operations, 19 tags
- `https://api.digitalairstrike.com/swagger/docs/v2` — DASWebAPI V2, 32 operations, 8 tags
- `https://api.digitalairstrike.com/swagger` — the rendered Swagger UI

The API is still served from the pre-2023 `digitalairstrike.com` brand domain; no
`api.dastechnology.com` host exists.

## What it covers

- **Accounts and hierarchy** — rooftops, parents, children, descendants, dealer-group hierarchies, packages, competitors.
- **Reputation / reviews** — review retrieval with rich filters, review responses, department disposition, review-site configuration and links, review stats by interval.
- **Surveys and NPS** — survey responses, dealer responses, SMS and email survey requests, survey stats, NPS stats over time.
- **Statistics** — enterprise, review, survey, survey-method and employee rollups across a list of accounts.
- **Messaging** — asynchronous and synchronous message send, delivery status and event polling by token, SMS number provisioning.
- **Users** — user records, settings, notification settings, report settings, password and welcome flows.
- **Vehicles and transactions** — VIN and car detail lookup, sale and service transactions.
- **Partner surfaces** — SOCi provisioning/deprovisioning, Zuora digital-signature request, Incentives programs, Media upload.

## How to call it

- Base URL: `https://api.digitalairstrike.com`, HTTPS only.
- Auth: `Authorization: Bearer <token>`. Probed 2026-08-12 — an anonymous request returns `401`
  with `WWW-Authenticate: Bearer`. Neither Swagger document declares a security scheme, and no
  public token endpoint exists (`/token` and `/oauth/token` both 404). Tokens are issued through
  the dealer/OEM/partner relationship, not through self-serve signup.
- Send `Accept: application/json`. The API also serves XML, and it returns XML on the error path
  regardless of what you asked for.
- Most resources are scoped by `accountGuid` (a rooftop UUID) in the path.
- v2 collections return `{ data, count }`; v1 collections return bare arrays.

## What it does NOT have

An agent should know these before planning against this API:

- **No documented errors.** All 136 operations declare only `200`. Live responses include `401`
  (XML), `404` (HTML, a different shape) and `500` (XML, currently carrying a full stack trace).
- **No idempotency.** No `Idempotency-Key` header on any of the 26 write operations, several of
  which send email, dispatch SMS surveys or provision phone numbers. A blind retry sends twice.
- **No rate limits.** None published, and no `RateLimit-*` or `Retry-After` header on the wire.
- **No webhooks, callbacks or AsyncAPI.** Delivery events are polled by token, not pushed.
- **No SDKs.** No first-party client library on npm, PyPI, NuGet, RubyGems or Maven Central.
- **No MCP server, no A2A agent card, no `/.well-known/` documents** on any host.
- **No status page, no changelog, no deprecation policy, no SLA.** One operation is flagged
  deprecated (`Client_GetClientSurveys`) with no replacement and no sunset date.
- **No pricing, no plans, no sandbox and no self-serve signup.** The only commercial entry point
  is a demo request form.
